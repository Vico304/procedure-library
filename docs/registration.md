# 注册、验收与复用

用户主动要求注册就是本次记录、适当测试与通过后本地启用的依据。仅在范围或关键输入不明确时询问；额外的重复任务提醒不构成注册前置条件。

## 流程包

`init` 在 `.local/drafts/<id>/` 创建草稿，其中：

- `procedure.json`：身份与版本、触发描述、输入契约、工具前提、复杂度与选型依据、执行配置、测试用例及准备器/检查器路径。
- `procedure.md`：目标、步骤目的、参数使用、分支、成功特征和停止条件。
- `scripts/`：可重复的具体操作。需要脚本时才增加，不把临时探索或无关清理纳入流程。
- `checks/prepare.py`：接受 `--workspace` 和 `--case`，建立隔离输入并输出参数 JSON。
- `checks/verify.py`：接受 `--workspace`、`--parameters`、`--result` 与可选 `--case`，独立核对实际产物。通过退出 0，失败非零；输出不作为公开验收记录的原文。

准备器和检查器会在控制端实际执行，注册者应先审阅这些代码。路径必须相对流程包并留在包内，拒绝符号链接。运行参数是私有绑定，和公开的参数契约分开保存。

参数类型支持 `string`、`integer`、`boolean`、`file`、`directory`。路径参数声明 `access: read` 或 `write`。读路径必须存在；写路径必须落在本次工作目录或显式 `--write-root` 范围内，写目录会作为 Codex 的附加工作目录传入。流程本身的授权不扩大宿主权限。

## 独立模型测试

`test` 对每个声明的用例创建新工作目录，运行准备器，再启动新的 `codex exec`，明确指定 `model` 和 `model_reasoning_effort`。执行器只收到执行材料和参数，不收到原会话、准备器或预期结果。

按任务复杂度选择 `routine`（6 Luna，默认 low）或 `complex`（6.1 Terra，默认 medium），登记 `complexity_reason`，以 `tools/model-policy.json` 为唯一选型规则来源。输入和步骤明确时用 Luna，较多分支判断、视觉或跨工具任务用 Terra；需要的推理强度在验收前确定，不能在重复执行时随意更换。

先用 `models` 查询目标 CLI 提供的这两个型号与推理强度。CLI 至少为 0.159；macOS 工具优先选桌面应用附带的兼容版本，也可用 `PROCEDURE_CODEX` 显式指定。CLI 需要访问已有登录状态与网络；沙箱阻断时使用宿主正常审批，不使用关闭权限检查的选项。型号不可用时停止，不替换为 5.6 或其他型号。

执行器输出固定的状态结构：`success`、`needs_input`、`blocked` 或 `failed`，以及摘要和产物列表。控制端同时检查退出结果、预期状态和独立检查器；模型不能通过一句“成功”自行验收。

从正常输入、关键参数变化和真实存在的停止条件中选择有意义的用例。测试目录应提供流程所需的原始材料；需要外部写入时使用明确允许的测试对象。只能验证到提交前的流程，就按这个范围记录。

检查器同时核对承诺保持不变的对象。例如输入文件必须保留原样时，由准备器保存输入指纹，再检查执行后的输入；只确认输出正确不足以验证这个约定。

默认失败后停止本轮测试。调整流程或检查器后重新验收，不手写通过报告；费用、工具或模型不可用时保留待验证状态。原始结果在 `.local/runs/`，精简公开记录不包含参数、路径、输出正文或会话 ID。

## 发布与安装

`promote` 必须接收完整真实测试报告。它核对流程内容、执行工具代码与选型规则、模型配置和全部用例，执行公开内容检查后，将版本放入 `procedures/<id>/` 并更新目录。已有版本只有在显式 `--replace` 且版本号改变时才替换。旧版证据保留在 Git 历史，不把旧型号的通过结果用于新配置。

启用插件格式后，发布会自动刷新 `skills/procedure-<id>/` 中的简短入口，入口引用统一的流程包和运行工具。`build-plugin` 打包公开运行材料；插件安装不包含本地参数与日志。使用 GitHub marketplace 分发时，提交并推送通过验收的源码，再刷新与更新插件。

`install` 只接受验收仍有效的版本，生成 `procedure-<id>` 技能，连同冻结的执行包和运行工具安装到指定技能目录。安装副本自包含，不依赖最初那台机器的流程库路径；不同环境使用自己的运行参数。

新任务通过技能描述匹配后，先检查本次输入与工具，再调用安装包中的运行入口。固定操作执行脚本，已测试的低成本模型负责步骤调度和有限判断。失败时返回具体原因及本地报告位置，不能静默换模型、扩大写入范围或修改规范。

修改流程、模型/强度、准备器、检查器或运行工具会使对应验收指纹失效。重新测试后再发布；原版本在新版本通过前继续保留。文档的适用范围不能扩大成未验证工具或环境的保证。

## 公开仓库与本地信息

公开文件只含通用规范、代码、参数契约、测试构造方法与精简验收记录。真实账号、服务器地址、个人路径、原始参数、凭据和日志留在 `.local/` 或临时目录。使用 `audit` 检查公开树，并核对 `git diff --cached` 后按当前授权推送。

云端先配置 Python、Codex 登录与流程要求的工具，再克隆此库。使用实际环境的工作目录和参数；环境变化影响流程行为时复测相关流程。无需预建服务、数据库或后台观察器。
