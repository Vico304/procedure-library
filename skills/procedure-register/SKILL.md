# 标准流程注册

用户主动要求注册，即在已说明范围内完成提取、测试与本地发布，无须再询问是否记录。重复任务提醒仅为附加功能：发现当前可见任务明显重复时可以简短建议，不做后台监控，不扫描其他会话。

## 找到流程库

公开流程库：`https://github.com/Vico304/procedure-library`。先使用用户指定位置或 `PROCEDURE_LIBRARY`，再读本技能目录中可选的 `.local/library.json` 的 `library_path`，最后查当前目录及父目录中的 `procedure-library/`。本机绑定仅保存在被忽略的 `.local/`，不进入公开库。没有本地副本时，在用户指定位置或当前工作区克隆该仓库；已有副本沿用当前版本，不自行拉取更新。

详细规范在流程库的 `docs/registration.md`，命令接口由 `python3 <流程库>/tools/procedure.py --help` 提供。流程、脚本和测试维护在流程库，技能入口只负责引导注册。

## 注册

1. 读取本次可访问的成功操作、原始输入和结果，确定可重复部分。流程尚未跑通时先完成实际任务，不能把推测标记为成功路径。独立桌面操作需由用户提供记录或使用宿主录制能力。
2. 按注册规范创建未安装的草稿。把真实路径、账号、日期等转成输入参数；记录前提、步骤、分支、结果检查和停止条件。固定操作用可读脚本，保留操作目的和判断依据。
3. 创建独立测试输入与检查器，用流程库 `test` 命令调用明确配置的低成本模型，使用新的会话和隔离工作目录执行。先用 `models` 核对目标 CLI 提供的型号及推理强度，并确认工具与测试对象可用；不能用主模型代跑、伪造测试结果或让执行器修改验收器以通过。CLI 的网络访问或状态目录写入受沙箱限制时，走宿主正常权限审批，不使用绕过审批或沙箱的选项。
4. 使用真实测试报告执行 `promote`。失败保留草稿并说明缺口；通过后执行 `install`，发布独立、简短的流程技能。真实绑定与原始日志只保留在 `.local/` 或临时目录，不写入公开文件。
5. 需要同步远端时先执行 `audit` 并审阅待提交文件，再按当前授权提交和推送。用户已要求发布到公开流程库的内容按该授权处理，不重复询问；不把本地业务输入或运行日志一并提交。

## 复用与修订

已发布流程由各自的技能描述匹配，执行时使用登记的模型与推理强度。输入、工具或前提不满足时报告具体停点；新问题交回主模型，不扩展任务或静默改用更强模型。流程或执行配置变更后，重新验收受影响版本再发布，保留现有可用版本直到新版本通过。

流程库可以在本地或云端使用。云端先检查所需命令、模型和工具，使用该环境的参数文件；仅把规范和已验证代码作为可移植内容，环境能力与具体执行结果按实际验证说明。
